{{- else if contains "NodePort" .Values.webapp.service.type }}
Get the application URL by running these commands:

  export NODE_PORT=$(kubectl get --namespace {{ .Release.Namespace }} -o jsonpath="{.spec.ports[0].nodePort}" services {{ include "airbyte.fullname" . }})
  export NODE_IP=$(kubectl get nodes --namespace {{ .Release.Namespace }} -o jsonpath="{.items[0].status.addresses[0].address}")
  echo http://$NODE_IP:$NODE_PORT
{{- else if contains "LoadBalancer" .Values.webapp.service.type }}
Get the application URL by running these commands:

  export SERVICE_IP=$(kubectl get svc --namespace {{ .Release.Namespace }} {{ include "airbyte.fullname" . }} --template "{{"{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}"}}")
  echo http://$SERVICE_IP:{{ .Values.webapp.service.port }}

NOTE: It may take a few minutes for the LoadBalancer IP to be available.
You can watch the status of by running 'kubectl get -n {{ .Release.Namespace }} svc -w {{ include "airbyte.fullname" . }}'

Auth: By default server.blotoutAuthEnabled is false, so only Airbyte built-in auth is used. Set server.blotoutAuthEnabled to true and set server.env_vars BLOTOUT_AUTH_ENDPOINT and BLOTOUT_BASE_URL to enable Blotout authorization.

Troubleshooting:
- 401 on /api/v1/auth/validation: Expected when there is no valid session (e.g. opening the URL in a new tab without logging in). The UI should redirect to Blotout login. If you get 401 after logging in, verify: (1) BLOTOUT_BASE_URL — if the server calls Blotout to validate tokens, this may need to be the Blotout auth service URL (e.g. https://auth.blotout.io), not the Airbyte URL; (2) cookies are sent (same domain; check Application → Cookies for your host).
- 403 on /api/v1: When BLOTOUT_AUTH_ENDPOINT and BLOTOUT_BASE_URL are set, the API requires Blotout auth. Open the app from the root URL (e.g. https://your-host/), log in via Blotout if prompted, then use the UI; do not call /api/v1 directly in the browser without a session.
- Sources or connections not loading / "Could not find configuration for STANDARD_SYNC: <id>": The UI may have a stale connection or workspace ID (e.g. after a DB recreate). Clear site data for this host: DevTools → Application → Storage → Clear site data for the Airbyte origin, then reload and open the app from the root URL.
